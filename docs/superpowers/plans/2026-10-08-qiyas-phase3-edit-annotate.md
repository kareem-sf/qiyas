# Qiyas Phase 3: Edit and Annotate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The QS can draw, modify and annotate drawings in Qiyas and save them so AutoCAD shows the same thing: the spec's feature groups 2, 3, 5, 7 and the rest of 6 and 8.

**Architecture:** Document edits go through the same command bus. Undo for document changes uses opencadcodec's entity change recording (`begin_entity_change_recording` / before images) so a command's inverse is the set of entities it added, removed or replaced, not a snapshot. Geometry operations (offset, trim, extend, fillet, intersections, triangulation for fills) come from `opencadkernel::geom2d`. Every tool is a small state machine in the frontend (`toolReducer` pattern) that collects points and entities and emits one command; prompts show in the command line and the status bar.

**Tech Stack:** opencadcodec (entities, transforms, explode, dimension and hatch structures, block records, attributes, layer states), opencadkernel (offset, clip, fillet, intersect, triangulate, polyline_edit, arrangement), existing viewport with fills (triangle lists) added to the batch.

**Spec:** `docs/superpowers/specs/2026-10-08-qiyas-design.md` ("Phase 3"). Feature numbers refer to `docs/research/2026-10-08-opencadstudio-features.md`.

## Global Constraints

- Everything from the earlier plans.
- Every document edit is one undoable command with before images; undo of a draw removes exactly what it added; redo re-adds with the same handles.
- Entities are created with the current layer, colour ByLayer, linetype ByLayer unless the properties palette says otherwise.
- Dimensions are written as real `Dimension` entities with their anonymous `*D` block generated by Qiyas (so AutoCAD renders them) and with the current `DimStyle`.
- Fills (hatch, solid, wipeout, text background) render as triangle lists in a new batch section; pattern hatches render their lines; solid and gradient hatches render as fills.
- Nothing from Open CAD Studio's GPL code is copied; its feature names are only a checklist.

## Review Focus

1. Trim a line against a circle where the line crosses twice: the clicked piece must go, both other pieces stay, and undo restores the single original line with its handle. Task 4.
2. A polyline drawn with arcs (bulges), offset outwards by 0.2 m, then measured: the offset must be a single closed polyline with arcs, area = original + perimeter×0.2 + π×0.2² within 1e-6. Task 4.
3. A linear dimension saved to DWG and opened in another viewer must show the same text and arrows (the anonymous block is complete). Task 6.
4. Creating a block from entities on three layers and inserting it rotated: the insert's nested colours and layers must render and count correctly, and "edit block in place" must change every insert. Task 8.
5. Clipboard copy from drawing A and paste into drawing B with a layer that does not exist in B: the layer is created with A's colour, and the handles are new. Task 10.

### Task 10: Clipboard, multiple viewports and tiling, UCS, sheet sets, backups and recovery

**Files:** clipboard: `CopyToClipboard{handles, base}` serialises entities + their layers/blocks/styles as DXF text in the system clipboard (`arboard` crate, MIT/Apache); `PasteFromClipboard{at}` imports with handle remapping and creates missing layers/blocks/styles; paper space: `MView{corner1, corner2}` creates a `Viewport` entity; the viewport renders model space inside paper-space viewports (second camera per viewport, clipped); `VpLayer` overrides; tile/cascade of file tabs (split view: two viewports side by side on the same or different drawings); `UCS{origin, x_axis}` (coordinates in the status bar and typed input use it); sheet set manager (a JSON `.qss` listing drawings and layouts, open/print all); backups: `*.bak` already; autosave every 5 minutes to `<name>.sv$` next to the drawing, and on launch a recovery dialog lists `.sv$` files newer than their drawing; `Audit` and `Recover` run the failsafe reader on a damaged file and report what was dropped.
- Tests: copy/paste across two sessions (Review Focus 5); MView creates a viewport entity that saves; autosave writes and the recovery dialog finds it.
